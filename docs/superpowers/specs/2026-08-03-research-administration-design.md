# Research administration — design

**Date:** 2026-08-03
**Status:** Approved for planning
**Author:** handoff for the implementing agent

## 1. Problem

The admin workspace has a **Contact inbox** (`messages`) section that is no longer
used. It must be removed.

In its place the admin needs to **manage research publications** the same way it
manages Content cases: create, edit, delete, search and filter — including the
research papers already shown on the public site — and attach images that are
uploaded to Cloudflare R2 and served through the cached media route.

Today research is **not** in the database. `app/lib/research.ts` fetches papers
live from the external `smarthealth.group` API, filters to Dr. Abdulwahid's
work, and falls back to four hardcoded records. Nothing about it is editable.

## 2. Decisions (locked)

1. **The database becomes the single source of truth.** A new Supabase
   `researches` table replaces the external feed. The live feed is read **once**
   to seed the table; after that the external API is no longer called.
2. **Import scope:** all **30** currently-active Dr. Abdulwahid papers from the
   live feed are imported (including breast-content papers — kept by explicit
   client instruction), preserving their existing external image URLs. The admin
   can prune or edit any of them afterward.
3. **Images per research:** one **cover image** (shown on the card and detail
   hero) plus a **gallery** of additional images shown on the detail page.
4. **Existing images:** imported papers keep their external image URL as-is.
   New/edited covers and all gallery images upload to R2 and serve through
   `/api/media/...`.

## 3. Non-goals

- No change to Content, Topics, Events, Contributors or People sections beyond
  removing the `messages` section and swapping one overview metric.
- No download/re-hosting of existing external images into R2.
- No new locale/translation work; research copy stays English-sourced as today.
- No slug column for research; the public URL stays the numeric id
  (`/:locale/research/:id`), which the current detail page already expects.

## 4. Architecture

### 4.1 Database — new migration `supabase/migrations/0009_research.sql`

Runs after `0008`. Idempotent (`if not exists`, `on conflict`) so it is safe to
re-run.

**`public.researches`**

| Column | Type | Notes |
|---|---|---|
| `id` | `bigint generated by default as identity primary key` | Imported rows insert their **source id** (e.g. 1358) so existing `/research/:id` URLs stay valid. New rows auto-generate. |
| `title` | `text not null` | |
| `authors` | `text` | Free-text byline, e.g. "Dr. A, Dr. B, and colleagues". |
| `abstract` | `text` | Plain text. |
| `journal` | `text` | |
| `category` | `text not null default 'Publication'` | Free text: "Paper", "Case Report", "Review". Not an enum — values vary. |
| `link` | `text` | External paper URL. |
| `published_date` | `date` | Drives display date, `year`, and sort order. |
| `status` | `public.content_status not null default 'published'` | Reuses the existing enum (`draft`/`scheduled`/`published`/`archived`). Only `published` shows publicly. |
| `cover_image_url` | `text` | Either a kept external URL or an R2 `/api/media/...` URL. |
| `created_at` | `timestamptz not null default now()` | |
| `updated_at` | `timestamptz not null default now()` | Maintained by the API on write (no DB trigger, matching `content_items`). |
| `updated_by` | `uuid references public.profiles(id) on delete set null` | |

Index: `researches_published_date_idx on (published_date desc)`.

After seeding, bump the identity sequence past the max imported id so new inserts
do not collide:
`select setval(pg_get_serial_sequence('public.researches','id'), (select max(id) from public.researches));`

**`public.research_media`** — mirrors `content_media`

| Column | Type |
|---|---|
| `id` | `uuid primary key default gen_random_uuid()` |
| `research_id` | `bigint not null references public.researches(id) on delete cascade` |
| `kind` | `public.media_kind not null default 'image'` |
| `storage_path` | `text not null` |
| `public_url` | `text not null` |
| `alt_text` | `text` |
| `caption` | `text` |
| `sort_order` | `integer not null default 0 check (sort_order >= 0)` |
| `created_at` | `timestamptz not null default now()` |

Index: `research_media_research_idx on (research_id, sort_order)`.

**RLS** (matching the content pattern):

- Enable RLS on both tables.
- `researches`: `for select using (status = 'published')`.
- `research_media`: `for select using (exists (select 1 from public.researches
  where id = research_id and status = 'published'))`.
- No public insert/update/delete policy — admin writes run as service role and
  bypass RLS.

**Seed:** insert the 29 papers (30 active minus the one title already excluded in
code — "giant malignant phyllodes tumor with ulceration…") via
`insert ... on conflict (id) do nothing`. Seed data is generated from the live
feed at implementation time (title, authors, abstract, journal, category, link,
published_date, cover_image_url, `status = 'published'`).

> Note: the client instruction was "keep them all." The one excluded title is
> preserved in the exclusion list purely to match the *current live site*, whose
> code already drops it. If the client wants that paper too, remove it from the
> exclusion and it seeds like the rest. Confirm during implementation; default is
> to match current behavior (29 rows).

### 4.2 Public reader — rewrite `app/lib/research.ts`

- `getResearches()` reads `researches` (status = published) + is wrapped in
  `unstable_cache` with `revalidate: 60` and tag `published-research`, exactly
  like `getLibraryContent` in `content.ts`.
- `getResearchById(id)` reads one published research **plus its `research_media`
  gallery**, cached per-id under the same tag.
- Row → `Publication` mapping: `imageUrl` ← `cover_image_url`; `year` ← first 4
  chars of `published_date`; `date` ← `published_date`; `media` ← gallery rows.
- The staff-portrait enrichment (`withStaffPortraits` / `contributorsFromNames`
  / `staffPortraitFor`) is **kept** — the detail page's author strip depends on
  it.
- External API fetch and `FALLBACK_PUBLICATIONS` are removed. On DB error,
  return `[]` (public page renders its empty state).

`Publication` type gains an optional `media?: { publicUrl: string; altText?:
string; caption?: string }[]` field for the gallery.

### 4.3 Admin API — `app/api/admin/[resource]/route.ts` + `app/lib/admin-server.ts`

**Remove `messages`:**
- Drop `"messages"` from `allowedResources` and from the `AdminResource` type.
- Remove the `contact_messages` count from the overview query; add a
  `researches` count in its place (`metrics.research`).
- Remove the `messages` GET branch.

**Add `research`:**
- `allowedResources` / `AdminResource` gain `"research"`.
- `admin-server.ts`: add `research` to `WRITABLE` and `DELETABLE` for the same
  roles that can write/delete `content` (owner, content_manager, editor for
  write; owner, content_manager, editor for delete — mirror content exactly:
  `WRITABLE` owner/content_manager/editor/contributor include content →
  research included the same way; `DELETABLE` owner/content_manager/editor).
- **GET `research`:** select
  `id,title,authors,abstract,journal,category,link,published_date,status,cover_image_url,created_at,updated_at,research_media(id,storage_path,public_url,kind,alt_text,caption,sort_order)`
  ordered by `updated_at desc`.
- **POST `research`:** validate title; coerce `status` to the enum (unknown →
  `draft`); preserve `published_date` on edit if already set and status stays
  published (parallel to content's `published_at` handling); write scalar fields
  + `updated_by` + `updated_at`; rewrite `research_media` as delete-then-insert
  with the same error-surfacing the content path uses. `cover_image_url` is taken
  verbatim from the body (already an external URL or an R2 public URL the editor
  set on upload).
- **DELETE `research`:** allowed; table `researches`. Cascade removes gallery.
- The `content`/`research` numeric-vs-uuid id difference needs no special
  handling — Supabase `.eq("id", value)` accepts the string form for a bigint
  column.

### 4.4 Admin UI — `app/components/AdminWorkspace.tsx`

- `Section` type: remove `"messages"`, add `"research"`.
- `nav`: remove the Contact inbox entry; add
  `{ id: "research", label: "Research", icon: IconFile }`.
- Overview `cards`: replace the `messages`/"Inbox messages" card with
  `{ key: "research", label: "Research publications", section: "research" }`.
- Add-button label: "Add research".
- `startNew()`: research template
  `{ title:"", authors:"", abstract:"", journal:"", category:"Paper", status:"published", published_date:"", link:"", cover_image_url:"", research_media:[] }`.
- **List filtering:** research gets its own filter bar — **Year** (distinct years
  from loaded rows), **Category** (distinct categories), **Status**, and Clear.
  Implemented alongside the existing content filter block; search still runs over
  the shared haystack (extend the haystack key list with `authors`, `journal`,
  `category`).
- **Editor (`section === "research"`):** fields — Title, Authors (text),
  Abstract (textarea), Journal, Category, Publication date (`type="date"`),
  Status (Select: published/draft/archived), External paper link (`type="url"`),
  **Cover image** (a small control: shows current `cover_image_url` preview; an
  "Upload cover" button reuses the R2 `upload()` and sets `cover_image_url` to
  the returned `publicUrl`; plus a plain URL input to keep/paste an external
  URL), and a **gallery** using the existing `MediaManager` bound to
  `research_media`.
- `upload()` is reused. For research it passes `topicSlug = "research"` and
  `caseSlug = title` so R2 keys land under `topics/research/<title>/…`
  (acceptable; the prefix is cosmetic). Cover upload and gallery upload share the
  same route; cover sets a scalar field, gallery appends to `research_media`.
- `save()` posts `{ ...form, media: form.research_media }` for research (the API
  reads gallery rows from `media`, same as content).

### 4.5 Public detail page — `app/[locale]/research/[id]/page.tsx`

- Render `paper.imageUrl` as a cover image in the detail hero when present.
- Add a **gallery section** after the abstract that maps `paper.media` to
  `<img>` served from `public_url` (an `/api/media/...` URL → cached). Reuse
  `LazyImage` if straightforward; otherwise a plain lazy `<img>` is acceptable.
- Card grid (`ResearchExplorer`) already renders `imageUrl`; no change needed.

### 4.6 Styles — `app/globals.css`

- Research detail cover + gallery grid (responsive, theme-aware, logical
  properties, no hardcoded letter-spacing per the RTL rule).
- Admin research filter bar can reuse `admin-content-filters` and existing admin
  form classes; add only what's missing (cover preview control).

## 5. Data flow

**Admin save:** editor form → `POST /api/admin/research` → service-role write to
`researches` + delete/insert `research_media` → within ≤60s the cached public
reader revalidates → public pages reflect changes. (Matches content's
eventual-consistency behavior; no explicit `revalidateTag` call, consistent with
the current content flow.)

**Image serving:** admin upload → `POST /api/admin/upload` → `MEDIA_BUCKET.put`
→ returns `/api/media/<key>` → stored in `cover_image_url` or `research_media` →
public page requests `/api/media/<key>` → edge cache serves repeat reads without
touching R2 (unchanged existing route).

## 6. Error handling

- Reader: DB error → `[]`; detail not found → `notFound()` (unchanged).
- API: same `apiError` conventions; delete-then-insert failures surface
  "Saved the item, but could not update media: …" like content.
- Upload: existing 10 MB guard, accepted types, and 413 handling apply
  unchanged.

## 7. Testing / verification

- `npx vinext build` (Windows-safe form), `npm run lint`, and the rendered-route
  test suite via the hook — all must pass. Keep `main` deployable.
- Manual QA (local preview):
  - Admin: Research list loads with imported papers; search + Year/Category/
    Status filters + Clear work; create, edit, delete a research; upload a cover
    and a gallery image and confirm they display.
  - Public: `/en/research` grid unchanged from user's view; a detail page shows
    cover + gallery; `/ar` and `/ckb` render without overflow; light/dark at
    375/768/1024/1440.
  - Confirm the `messages` section is gone from nav and overview.
- The migration must be applied to Supabase before the reader returns data;
  until then the public list is empty (acceptable, flagged to client).

## 8. Rollout notes

- This is a DB-backed feature: the migration `0009_research.sql` must be run
  against Supabase (via the client's migration process) for research to appear.
- No new environment bindings — reuses `MEDIA_BUCKET`, Supabase service role,
  and the read-through content cache already in place. (That cache was Workers
  KV when this was written; it is the `smart-cache` R2 bucket since
  2026-08-31.)
- Work stays local until the client explicitly asks to publish (per handoff
  working agreement).
